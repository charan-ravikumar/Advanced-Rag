RAG Platform Overview

The NovaMind RAG (Retrieval-Augmented Generation) Platform is a managed enterprise service that enables your applications to answer natural-language questions grounded in your proprietary documents. It handles the full pipeline: document ingestion, chunking, embedding, indexing, retrieval, re-ranking, and LLM-augmented generation.

Version 1.0 reached General Availability (GA) on August 14, 2025. Version 1.1, featuring streaming responses and citation highlighting, is expected in November 2025.

Getting Started

Follow these steps to ingest your first document and run a retrieval query in under 10 minutes.

Step 1 — Generate an API Key

Log in to the NovaMind Dashboard, navigate to Settings → API Keys, and click Create New Key. Keys use HMAC-SHA256 signing and must be rotated every 90 days per security policy.

Step 2 — Create a Namespace

curl -X POST https://api.novamind.ai/v1/rag/namespaces \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "my-knowledge-base", "region": "us-east-1", "embedding_model": "nm-embed-768"}'

Step 3 — Ingest a Document

curl -X POST https://api.novamind.ai/v1/rag/namespaces/my-knowledge-base/ingest \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@company_policy.pdf" \
  -F "metadata={\"department\":\"HR\",\"version\":\"2025-Q3\"}"
ℹ️
Ingestion is asynchronous. Poll GET /namespaces/{id}/jobs/{job_id} until status returns COMPLETED. Typical ingestion time: 30–90 seconds for a 50-page PDF.

Step 4 — Query Your Knowledge Base

curl -X POST https://api.novamind.ai/v1/rag/namespaces/my-knowledge-base/generate \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is the company travel reimbursement policy?",
    "top_k": 5,
    "include_citations": true,
    "llm": "gpt-4o"
  }'
✅
You are now live! The /generate endpoint retrieves relevant chunks and returns an LLM-generated answer with source citations.

Document Ingestion

The ingestion pipeline transforms raw documents into searchable vector representations through five stages: Parsing → Chunking → Embedding → Indexing → Metadata Storage.

Chunking Configuration

You can customize chunking behavior per namespace:

Retrieval & Search

The RAG Platform uses a hybrid retrieval strategy: dense vector search (NM-Embed-768 + Pinecone HNSW) combined with sparse BM25 search (Elasticsearch), fused via Reciprocal Rank Fusion (RRF) and re-ranked by a cross-encoder model.

Retrieval Parameters

ParameterDefaultDescription
top_k5Number of chunks returned (1–20)
retrieval_modehybriddense, sparse, or hybrid
reranktrueApply cross-encoder re-ranking to fused results
score_threshold0.3Minimum relevance score (0–1); chunks below threshold excluded
filternullMetadata filter (JSON); e.g., {"department":"HR"}
include_citationsfalseInclude source document and page references in response

Frequently Asked Questions

How long does document ingestion take?
Ingestion is asynchronous. A typical 50-page PDF takes 30–90 seconds. XLSX files with many sheets may take 2–5 minutes. You can poll the job status endpoint to track progress. Ingestion throughput is rated at 10,000 pages per minute at the platform level.
Which LLMs are supported for generation?
The /generate endpoint currently supports: OpenAI GPT-4o (default), GPT-4o mini, Anthropic Claude 3.5 Sonnet, and NovaMind Llama 3 70B (hosted on-prem). You can specify the model with the llm parameter. Additional models will be added in Q4 2025.
Is my data used to train NovaMind models?
No. Customer document data is strictly isolated per namespace and is never used to train or fine-tune NovaMind models. Your data is encrypted at rest (AES-256) and in transit (TLS 1.3). Enterprise customers can request a dedicated, single-tenant deployment. See our Data Processing Agreement for full details.
What is the difference between /query and /generate?
POST /query returns the top-k raw chunks with relevance scores — useful for building custom generation logic. POST /generate calls retrieval internally and passes results to an LLM to produce a natural-language answer with optional citations. Use /query for maximum control; use /generate for drop-in RAG responses.
How do I delete a document from a namespace?
Send a DELETE request to /namespaces/{namespace_id}/documents/{document_id}. This removes the document record and all associated chunks from both the vector index and the metadata store. Deletion is permanent and cannot be undone. The operation typically completes in under 5 seconds.
What happens if my document contains mixed languages?
The embedding model NM-Embed-768 supports English, Spanish, French, German, and Portuguese. Documents in other languages will be ingested but retrieval quality may be significantly degraded. We recommend converting non-English documents to English before ingestion. Multi-language support is on the Q1 2026 roadmap.
How are scanned PDFs handled?
If the PDF extractor detects fewer than 50 characters per page (a signal the document is scanned/image-based), it automatically falls back to Tesseract OCR. OCR adds approximately 3–10 seconds per page. OCR accuracy depends on scan quality; 300 DPI or higher is recommended. Non-English OCR accuracy is limited to Tesseract's supported language packs.

Troubleshooting

Error: 429 Too Many Requests

You have exceeded your plan's rate limit. Default limits: Starter = 60 req/min, Professional = 600 req/min, Enterprise = custom. Implement exponential backoff with jitter. Contact support@novamind.ai to request a limit increase.

Error: Ingestion job stuck in PENDING

If a job remains in PENDING status for more than 10 minutes:

  • Verify your file is not corrupted and is under the plan file size limit
  • Check the Status Page for active platform incidents
  • Re-submit the ingestion request with a new API call (safe to retry — idempotent by content hash)
  • If the issue persists, open a support ticket with the job_id

Poor retrieval quality / irrelevant results

Try the following in order:

  1. Switch retrieval_mode to hybrid if using dense or sparse alone
  2. Lower score_threshold from 0.3 to 0.2 to broaden results
  3. Ensure your document was fully ingested (check chunk_count in the job result)
  4. Re-phrase your query to be more specific and avoid ambiguous pronouns
  5. Review chunk size — for dense technical documents, reducing chunk_size to 256 tokens often improves precision
